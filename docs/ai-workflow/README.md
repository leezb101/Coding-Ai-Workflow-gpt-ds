# AI Workflow Guide

This project uses an AI-assisted engineering workflow with Codex Desktop and DeepSeek.

## Policy Source

`AGENTS.md` is the workflow policy source of truth for this project.

This README is a user guide only. If this guide conflicts with `AGENTS.md`, follow `AGENTS.md`.

## Roles

- Codex Desktop: workflow coordinator, project reader, implementation executor, verification runner
- GPT vision capability: visual, screenshot, UI, PDF, and browser-page understanding
- DeepSeek V4-Pro: external reasoning assistant for complex planning, architecture, long-context analysis, and difficult bug diagnosis

## Workflow Files

- `intake.md`: task classification and workflow routing
- `task.md`: user goal, constraints, acceptance criteria
- `context.md`: project context and relevant code summary
- `vision-spec.md`: visual, PDF, UI, screenshot, or browser-derived specification
- `deepseek-plan.md`: reasoning plan generated by DeepSeek
- `implementation-plan.md`: implementation plan adapted to the real codebase
- `execution-report.md`: final implementation and verification report

## Skill Layer

Skills are execution aids, not policy sources. `AGENTS.md` remains the workflow policy source of truth.

Skills live in:

    docs/ai-workflow/skills/

Codex should select relevant skills during intake, context preparation, and planning. Selected skills should be recorded in:

- `docs/ai-workflow/intake.md`
- `docs/ai-workflow/context.md`
- `docs/ai-workflow/implementation-plan.md`
- `docs/ai-workflow/execution-report.md`

Current available skills:

- `change-control.md`
- `context-selection.md`
- `codegraph.md`
- `testing-verification.md`
- `refactor-safety.md`

CodeGraph should be used to narrow context, not expand it blindly. Do not paste full project graphs into workflow files. Record only concise task-relevant graph findings.

## Standard Workflow

### 1. Start with Intake

For every new task, ask Codex Desktop to classify it first.

Prompt to use:

    Please follow AGENTS.md.

    Do not modify business code first.

    Create or update docs/ai-workflow/intake.md for the following request:

    [describe the request here]

    After intake, tell me:
    1. task type
    2. risk level
    3. whether DeepSeek is recommended
    4. whether visual analysis is needed
    5. whether code can be modified immediately
    6. next action

### 2. Simple Task

For small, clear, low-risk tasks, use this prompt:

    Please follow AGENTS.md.

    Based on docs/ai-workflow/intake.md, create or update docs/ai-workflow/task.md, then implement the task with minimal changes.

    After implementation, run relevant verification commands and update docs/ai-workflow/execution-report.md.

### 3. Complex Task

For difficult bugs, architecture questions, long-context reasoning, or cross-file changes, use this prompt:

    Please follow AGENTS.md.

    Do not modify business code.

    Based on the current request, create or update:
    - docs/ai-workflow/task.md
    - docs/ai-workflow/context.md

    The context should include:
    1. relevant files
    2. current behavior
    3. expected behavior
    4. suspected problem areas
    5. verification commands
    6. selected code snippets useful for DeepSeek

Then run DeepSeek planning:

    export DEEPSEEK_API_KEY="your_api_key_here"
    node scripts/ai/deepseek-plan.mjs

Then return to Codex Desktop and use this prompt:

    Please follow AGENTS.md.

    Read:
    - docs/ai-workflow/task.md
    - docs/ai-workflow/context.md
    - docs/ai-workflow/deepseek-plan.md

    Create or update docs/ai-workflow/implementation-plan.md.

    Then implement in small safe steps, run verification, and update docs/ai-workflow/execution-report.md.

### 4. Visual / UI / PDF / Browser Task

For tasks involving screenshots, UI designs, visual bugs, PDFs, or browser pages, use this prompt:

    Please follow AGENTS.md.

    Do not modify business code.

    Based on the screenshot, UI, PDF, or browser page, create or update:
    - docs/ai-workflow/vision-spec.md
    - docs/ai-workflow/task.md
    - docs/ai-workflow/context.md if code changes are needed

    The vision spec should include:
    1. visual structure
    2. observed problem
    3. expected result
    4. relevant UI elements
    5. possible code areas
    6. acceptance criteria
    7. uncertainties

Then run:

    export DEEPSEEK_API_KEY="your_api_key_here"
    node scripts/ai/deepseek-plan.mjs

Then return to Codex Desktop for implementation.

### 5. High-Risk Refactor

For large refactors, migrations, architecture changes, or large animation rewrites, use this prompt:

    Please follow AGENTS.md.

    Do not modify business code.

    Create or update:
    - docs/ai-workflow/intake.md
    - docs/ai-workflow/task.md
    - docs/ai-workflow/context.md
    - docs/ai-workflow/implementation-plan.md

    Break the implementation into phases.

    Do not implement until the plan is reviewed.

If DeepSeek is recommended, run:

    export DEEPSEEK_API_KEY="your_api_key_here"
    node scripts/ai/deepseek-plan.mjs

Then ask Codex Desktop to adapt the DeepSeek plan to the real codebase.

## DeepSeek Script

The DeepSeek plan script is located at:

    scripts/ai/deepseek-plan.mjs

Run it with:

    export DEEPSEEK_API_KEY="your_api_key_here"
    node scripts/ai/deepseek-plan.mjs

Optional model override:

    export DEEPSEEK_MODEL="deepseek-v4-pro"
    node scripts/ai/deepseek-plan.mjs

The script reads:

- `docs/ai-workflow/intake.md`
- `docs/ai-workflow/task.md`
- `docs/ai-workflow/context.md`
- `docs/ai-workflow/vision-spec.md`

It writes:

- `docs/ai-workflow/deepseek-plan.md`

For non-visual tasks, current policy is that old visual specs must not be reused blindly. The script should treat `vision-spec.md` as not applicable unless intake says visual analysis is needed.

## Important Rules

1. Do not let DeepSeek directly edit the project.
2. Treat DeepSeek output as advisory.
3. Codex Desktop must compare DeepSeek's plan against the real codebase.
4. Prefer minimal changes.
5. Do not introduce new dependencies unless explicitly required.
6. Always verify after implementation.
7. Always update `execution-report.md` after implementation.
