# AI Workflow Setup Summary

The project now has a structured AI workflow under `docs/ai-workflow/`, coordinated by `AGENTS.md` and supported by local scripts under `scripts/ai/`.

Completed work includes:

- A project-level workflow policy in `AGENTS.md`.
- A user-facing workflow guide in `docs/ai-workflow/README.md`.
- A reusable prompt handbook in `docs/ai-workflow/prompts.md`.
- Task-scoped workflow scratch files for intake, task definition, context, visual specs, DeepSeek plans, implementation plans, and execution reports.
- A DeepSeek planning script at `scripts/ai/deepseek-plan.mjs`.
- A reset script at `scripts/ai/reset-ai-workflow.mjs`.
- A workflow architecture review report at `docs/ai-workflow/workflow-review-report.md`.
- First-round hardening for source-of-truth rules, stale-file handling, task metadata, conditional visual-spec input, and reset warnings.

## 2. Core File Structure

Policy and guides:

- `AGENTS.md`: workflow policy source of truth.
- `docs/ai-workflow/README.md`: user guide.
- `docs/ai-workflow/prompts.md`: prompt handbook.
- `docs/ai-workflow/setup-summary.md`: setup closeout summary.

Task-scoped workflow files:

- `docs/ai-workflow/intake.md`: task classification and workflow routing.
- `docs/ai-workflow/task.md`: goal, constraints, scope, and acceptance criteria.
- `docs/ai-workflow/context.md`: project context and relevant code/file summary.
- `docs/ai-workflow/vision-spec.md`: visual, UI, PDF, browser, or screenshot-derived specification.
- `docs/ai-workflow/deepseek-plan.md`: external advisory plan generated by DeepSeek.
- `docs/ai-workflow/implementation-plan.md`: Codex-adapted implementation plan.
- `docs/ai-workflow/execution-report.md`: final implementation and verification report.
- `docs/ai-workflow/workflow-review-report.md`: architecture review of the workflow system.

Scripts:

- `scripts/ai/deepseek-plan.mjs`: reads workflow inputs and generates `deepseek-plan.md` via DeepSeek.
- `scripts/ai/reset-ai-workflow.mjs`: resets workflow scratch files to templates.

## 3. Tool Responsibilities

Codex Desktop:

- Coordinates the workflow.
- Reads project files and workflow artifacts.
- Performs intake, context gathering, implementation, and verification.
- Adapts DeepSeek output to the real codebase before making changes.
- Produces `implementation-plan.md` and `execution-report.md` when implementation occurs.

Codex CLI:

- Can run local commands and scripts.
- Useful for syntax checks, test commands, file search, and workflow script execution.
- Should follow the same `AGENTS.md` policy when used for this project.

DeepSeek:

- External reasoning assistant for complex planning, architecture review, difficult debugging, and long-context analysis.
- Does not edit files directly.
- Produces advisory content in `docs/ai-workflow/deepseek-plan.md`.
- Must be checked by Codex against the real codebase before implementation.

## 4. Standard Usage Flow

1. Start with intake:
   - Create or update `docs/ai-workflow/intake.md`.
   - Classify task type, risk level, visual need, DeepSeek need, direct implementation permission, required files, and next action.

2. Define the task:
   - Create or update `docs/ai-workflow/task.md`.
   - Capture goal, constraints, acceptance criteria, and out-of-scope items.

3. Prepare context when needed:
   - Create or update `docs/ai-workflow/context.md`.
   - Include relevant files, current behavior, expected behavior, architecture notes, suspected areas, and verification commands.

4. Prepare visual spec when needed:
   - Create or update `docs/ai-workflow/vision-spec.md` only for visual/UI/PDF/browser tasks.

5. Run DeepSeek only when recommended:
   - Run `node scripts/ai/deepseek-plan.mjs`.
   - Treat `deepseek-plan.md` as advisory.

6. Create an implementation plan:
   - Create or update `docs/ai-workflow/implementation-plan.md`.
   - Compare all plans against the real codebase.

7. Implement:
   - Make minimal, scoped changes.
   - Do not modify unrelated files.

8. Verify:
   - Run the smallest relevant verification first.
   - Run broader checks when warranted.

9. Report:
   - Create or update `docs/ai-workflow/execution-report.md`.

## 5. When DeepSeek Is Needed

Use DeepSeek when the task involves:

- Complex reasoning across many files.
- Architecture review or workflow/process review.
- Difficult bugs with unclear runtime behavior.
- High-risk refactors or migrations.
- Long-context analysis where a second planning pass is useful.
- A visual/UI issue that also involves complex architecture or state behavior.

DeepSeek should receive prepared workflow inputs, not raw vague requests.

## 6. When DeepSeek Is Not Needed

Do not use DeepSeek for:

- Simple low-risk implementation tasks.
- Small copy, style, or localized behavior changes.
- Intake-only tasks.
- Tasks where Codex can directly inspect the code and implement safely.
- Non-visual tasks with stale `vision-spec.md` content.
- Any task where the user explicitly says not to call DeepSeek.

## 7. Visual / UI / PDF / Browser Tasks

For visual tasks:

- Create or update `docs/ai-workflow/vision-spec.md`.
- Record source, observed problem, expected result, relevant UI elements, possible code areas, acceptance criteria, and uncertainties.
- Use screenshots, browser observations, or PDF details when available.
- If no visual evidence is available, say that the visual spec is preliminary.
- Only run DeepSeek if intake recommends it.

For non-visual tasks:

- Do not blindly reuse old `vision-spec.md`.
- `deepseek-plan.mjs` now inserts `Vision spec is not applicable for this task.` unless intake explicitly says visual analysis is needed.

## 8. Script Usage

Reset workflow scratch files:

```bash
node scripts/ai/reset-ai-workflow.mjs
```

This overwrites current workflow scratch files:

- `intake.md`
- `task.md`
- `context.md`
- `vision-spec.md`
- `deepseek-plan.md`
- `implementation-plan.md`
- `execution-report.md`

It preserves:

- `AGENTS.md`
- `docs/ai-workflow/README.md`
- `docs/ai-workflow/prompts.md`
- `docs/ai-workflow/workflow-review-report.md`

Run DeepSeek planning:

```bash
export DEEPSEEK_API_KEY="your_api_key_here"
node scripts/ai/deepseek-plan.mjs
```

Optional model override:

```bash
export DEEPSEEK_MODEL="deepseek-v4-pro"
node scripts/ai/deepseek-plan.mjs
```

Syntax checks:

```bash
node --check scripts/ai/deepseek-plan.mjs
node --check scripts/ai/reset-ai-workflow.mjs
```
